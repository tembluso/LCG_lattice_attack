# Cryptanalysis of a full-period 128-bit LCG

## Abstract

This project studies whether a long period protects a linear congruential
generator from prediction. The selected generator has modulus `2^128` and
satisfies the full-period conditions, yet its linear structure permits state
recovery. A complete-output baseline first recovers the unknown multiplier and
increment from three outputs. The main contribution then recovers complete
128-bit states when each output reveals only its 24 most significant bits. A
lattice formulation, LLL basis reduction, and Babai nearest plane recover 104
hidden bits per output from six observations. The attack succeeded for 100 of
100 randomized seeds and predicted every held-out output. A 1,050-trial matrix
maps the recovery boundary as leakage and observation count change.

## 1. Generator and threat model

The internal state follows

```text
X[n+1] = (a X[n] + c) mod m
```

with

```text
m = 2^128
a = 6364136223846793005
c = 1442695040888963407
```

For a power-of-two modulus, an odd increment and `a = 1 mod 4` satisfy the
full-period conditions. Therefore, the generator traverses all `2^128` states
before repeating.

The attacker knows the algorithm, `m`, `a`, `c`, output format, and order of
outputs. The internal state and hidden output bits remain secret. This follows
the normal cryptographic assumption that security should not depend on hiding
the design.

## 2. Complete-output baseline

Given three consecutive complete outputs `X0`, `X1`, and `X2`, define

```text
d0 = X1 - X0 mod m
d1 = X2 - X1 mod m
```

Then

```text
a = d1 * inverse(d0) mod m
c = X1 - a X0 mod m
```

The selected full-period parameters make `d0` odd, so it has an inverse modulo
`2^128`. The standalone baseline recovered both parameters and predicted the
fourth output in 1,000 of 1,000 randomized trials. This result is deliberately
presented as motivation, not the assessed technical contribution.

## 3. Truncated output model

If the generator reveals `s` high bits and hides `r = 128 - s` low bits, each
state can be written as

```text
X[i] = B Y[i] + e[i]
B = 2^r
0 <= e[i] < B
```

`Y[i]` is public and `e[i]` is the hidden low portion. The scaled observation
`B Y[i]` is therefore a numerical approximation of the complete state with a
bounded error.

Substitution into the recurrence gives connected modular constraints:

```text
e[i+1] - a e[i] = a B Y[i] + c - B Y[i+1] mod m
```

The modular equations alone have many representatives. Truncation identifies
the relevant solution because every hidden coordinate lies in a small known
interval.

## 4. Removing the affine increment

Define public offsets

```text
D[0] = 0
D[i+1] = a D[i] + c mod m
```

and transformed states

```text
Z[i] = X[i] - D[i] mod m
```

The increment cancels:

```text
Z[i+1] = a Z[i] mod m
```

For `n` observations, valid transformed sequences belong to the lattice
generated by

```text
(1, a, a^2, ..., a^(n-1)) mod m
(0, m, 0, ..., 0)
(0, 0, m, ..., 0)
...
```

The observations construct the target

```text
U[i] = B Y[i] - D[i]
```

The true transformed sequence is close to `U`; their displacement is the
hidden-error vector.

## 5. LLL and Babai

The original lattice basis contains long, poorly shaped vectors. LLL applies
reversible integer reductions and swaps to produce a shorter, more orthogonal
basis for the same lattice. Gram-Schmidt vectors guide the geometry but do not
generally belong to the lattice.

Babai nearest plane rounds projections in the reduced basis to find a nearby
lattice point. Babai is approximate, so the program validates every candidate:

- hidden coordinates must satisfy their bit bounds;
- recovered states must reproduce the observed high bits;
- consecutive states must satisfy the recurrence; and
- the final recovered state must predict a held-out output.

## 6. Main result

The main configuration uses:

```text
state size             128 bits
visible per output      24 bits
hidden per output      104 bits
observations              6
held-out outputs           1
```

A single leak remains compatible with `2^104` complete states. Exhaustive
search is infeasible. Across 100 deterministic randomized seeds, the attack
recovered the exact complete-state sequence in 100 cases and predicted all 100
held-out outputs.

The program separates one-time public-parameter precomputation from per-victim
work. LLL preparation depends on the public generator and observation count.
Each victim supplies only a new target. In the committed 100-trial reference
run, reusable preparation took hundreds of milliseconds while mean
victim-specific recovery took less than one millisecond. Runtime varies by
environment, so the exact nanosecond measurements remain in the final CSV
output instead of being treated as a fixed property of the attack.

## 7. Recovery boundary

The matrix used the same 30 victim seeds for every configuration:

```text
successes out of 30

visible bits \\ observations    3   4   5   6   7   8   9
16                            0   0   0   0   0   0  30
24                            0   0   0  30  30  30  30
32                            0   1  30  30  30  30  30
48                           30  30  30  30  30  30  30
64                           30  30  30  30  30  30  30
```

Less leakage per output requires more observations. Merely matching the state
size with nominally exposed bits did not ensure recovery. `16 * 8 = 128`
produced no successes, while `32 * 4 = 128` produced one success. Outputs are
related, their visible bits need not form independent constraints, and Babai is
approximate. The product of visible bits and observation count is a heuristic,
not a proof.

## 8. Artificial reset-code demonstration

The artificial service represents a website that issues password-reset codes.
It uses one global LCG for every account and returns a six-character hexadecimal
code derived from the top 24 state bits. The attacker is an ordinary registered
user who legitimately requests six codes for its own account. Those six values
are the only service outputs supplied to the recovery algorithm.

After recovering the generator state, the attacker commits to `d598b4` as the
next code. A different account, called the victim, then requests a reset code.
The service issues `d598b4`, matching the value committed before the victim
request. This ordering demonstrates prediction rather than postdiction.

The victim can be any account whose request produces the next output from that
same vulnerable global generator. The scenario does not imply that an attacker
can target an arbitrary Internet user. It assumes public parameters, six
consecutive observations, a shared generator, the stated truncation format,
and no unknown intervening request. If another request occurs first, the
prediction applies to that output instead of the intended victim.

## 9. Limitations and mitigation

The study covers one known-parameter power-of-two LCG and selected high-bit
leakage patterns. It does not recover unknown parameters from truncated output,
prove optimal observation counts, or establish universal success. Exact LLL
using Python fractions prioritizes clarity over performance.

Security-sensitive tokens should use a cryptographically secure generator such
as Python's `secrets` interface. Real reset systems also require sufficient
entropy, expiration, single use, rate limiting, and isolation between requests.

## 10. Reproducibility

All Python programs are standalone and use only the standard library. The
experiment RNG seed, generator parameters, raw trials, aggregated results,
environment information, and SHA-256 manifest are included. Run:

```powershell
python .\code\03_verify_project.py --full
```
